# واجهات برمجية ناقصة في الباك إند

توثيق لكل نقطة API يحتاجها الفرونت إند ولا توجد حالياً في الباك إند (`menu_syria_backend`)، بالترتيب حسب الأولوية. كل نقطة هنا تم التحقق من غيابها مباشرة من كود الباك إند (controllers/DTOs الفعلية)، وليست تخميناً.

---

## 1. إحصائيات المنتج الواحد (أولوية عالية)

الفرونت إند يرسل بالفعل نبضات التحليلات لكل منتج:
- `POST /public/items/:id/view` — عند فتح تفاصيل المنتج (موجود ويعمل)
- `POST /public/items/:id/cart-add` — عند الإضافة للسلة (موجود ويعمل)

لكن **لا توجد نقطة لقراءة هذه الإحصائيات مجمّعة لكل منتج**. مودل "إحصائيات المنتج" في لوحة التحكم (`item-stats-modal.tsx`) وبادج المشاهدات في كرت المنتج جاهزان بالكامل في الفرونت إند وينتظران هذه النقطة فقط.

**المطلوب:**
```
GET /statistics/items/:id?dateFrom=&dateTo=
```
نفس صلاحيات `/statistics/*` الحالية (JWT + تحقق ملكية المنتج + بوابة خطة الاشتراك `hasStatistics`).

**شكل الاستجابة:**
```json
{
  "itemId": "string",
  "viewCount": 0,
  "cartAddCount": 0,
  "quantitySold": 0,
  "revenue": 0,
  "favoriteCount": 0,
  "conversionRate": 0,
  "period": { "from": "ISO date", "to": "ISO date" }
}
```

## 2. تفعيل/تعطيل قسم ساعات العمل

لا يوجد أي حقل لساعات العمل في الباك إند حالياً إطلاقاً — القسم في الواجهة العامة يظهر دائماً "لم تُضف ساعات العمل بعد" لأن لا بيانات تصل من أي مكان.

**المطلوب على `Business` entity** (وليس `RestaurantProfile`/`RetailProfile` — المطاعم والمتاجر تحتاجه بالتساوي):
```
openingHoursEnabled: boolean   // افتراضياً false
openingHours: jsonb            // مصفوفة من 7 عناصر، index 0 = الأحد
```
كل عنصر في المصفوفة: `{ opens: string, closes: string } | null` — `null` يعني يوم إغلاق.

**على `UpdateBusinessDto`:** إضافة الحقلين كاختياريين (`@IsOptional`)، مع تحقق أن المصفوفة طولها 7 بالضبط عند إرسالها.

**على الاستجابات العامة الأربع** (`GET /restaurants/:slug`, `/stores/:slug`, `/public/businesses/:slug`, و`/menu/:slug` المتداخل تحت `restaurant`): إرجاع `openingHours` **فقط إذا كان `openingHoursEnabled = true`** — بهذا تعطيل القسم من لوحة التحكم يخفي الساعات فوراً دون حذف البيانات المحفوظة، ويحافظ على المنطق الموجود فعلاً بالفرونت إند ("الحقل غائب = لم يُنشر بعد").

## 3. حذف حساب مستخدم (لوحة الأدمن)

`users.controller.ts` يعرض حالياً `GET /users`، `GET /users/:id`، و`PATCH /users/:id/status` فقط (الحظر/إلغاء الحظر مُفعّل بالفرونت إند بالفعل). **لا يوجد أي مسار حذف** — زر "حذف المستخدم" غير موجود في قائمة إجراءات كرت المستخدم بلوحة الأدمن لهذا السبب تحديداً (بدل اختلاق زر لا يعمل).

**المطلوب (إن رغبتم بتفعيل هذه الميزة):**
```
DELETE /users/:id
```
بنفس صلاحيات `SUPER_ADMIN` المستخدمة في بقية مسارات الأدمن.

---

## 4. صفحة تفاصيل مستخدم واحد (ليست API — ملاحظة فرونت إند)

لا توجد صفحة `/admin/users/:id` في الفرونت إند حالياً — فقط قائمة المستخدمين. "عرض التفاصيل" في قائمة إجراءات الكرت يعرض حالياً "قريباً" بدل رابط فعلي. هذا لا يحتاج شيئاً من الباك إند، فقط صفحة جديدة يجب بناؤها لاحقاً في الفرونت إند.
